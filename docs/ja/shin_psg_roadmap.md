## プラットフォーム・言語方針

### 対応プラットフォーム

Windows / macOS / Linux の3プラットフォームを同等にサポートする。

### 推奨言語・スタック（検討候補）

| 層 | 候補 | 理由 |
|---|---|---|
| コアエンジン | C++ (C++17以上) | 音源エミュレータが軒並みC++、リアルタイム処理に有利 |
| スクリプト・バインディング | Rust または Python binding | クロスプラットフォームビルドの容易さ |
| GUI・ツール類 | Qt6 または Tauri (Rust+WebView) | クロスプラットフォームGUI |
| ライブ統合層 | Python または Node.js | YouTube API / OBS WebSocket連携の豊富なライブラリ |
| ビルドシステム | CMake | C++クロスプラットフォームのデファクトスタンダード |

※ 言語・ライブラリは Phase 1 の技術検証を経て確定する。

## サウンドエンジン候補ライブラリ（調査済み）

### FM音源系

| ライブラリ | 対応チップ | ライセンス | 備考 |
|---|---|---|---|
| **ymfm** | OPM/OPN/OPL系全般 | BSD-3-Clause | MAMEプロジェクト由来・C++14・高精度 |
| **libADLMIDI** | OPL3 (YMF262) | LGPL2.1+/MIT混在 | MIDI連携・複数チップ仮想化対応 |
| **libOPNMIDI** | OPN2 (YM2612) / OPNA (YM2608) | LGPL2.1+/MIT混在 | libADLMIDIの姉妹ライブラリ |
| **Nuked-OPM** | OPM (YM2151) | LGPL2.1+ | X68000系に対応・高精度 |

### PSG系

| ライブラリ | 対応チップ | ライセンス | 備考 |
|---|---|---|---|
| **ayumi** | AY-3-8910 / YM2149 | MIT | MSX・ZX Spectrumの標準PSG |
| **emu2149** | YM2149 / PSG | MIT | 軽量・組み込みやすい |
| **mame内蔵コア** | SN76489等 | BSD/GPL混在 | 要ライセンス精査 |

### オーディオ出力

| ライブラリ | ライセンス | 備考 |
|---|---|---|
| **SDL2 Audio** | zlib | クロスプラットフォーム・実績豊富 |
| **PortAudio** | MIT | 低レイテンシ・プロ向け |
| **miniaudio** | MIT/Unlicense | ヘッダオンリー・依存なし・最軽量 |

**第一候補：ymfm（FM）+ ayumi（PSG）+ miniaudio（出力）**
理由：いずれもMITまたはBSD系に近いライセンス、C++との親和性が高い。

## Phase 6：ステージング・オーディエンス対応

**目標：** 演奏会・ライブ本番モードの実装とオーディエンス数による感情影響の実現

### ステージングについて

シン・PSGの演奏環境は以下の3モードに区別される。

| モード | 説明 |
|---|---|
| プラクティス（Practice） | 練習・テスト演奏。オーディエンスなし。感情の入り方が控えめ。 |
| ステージング（Staging） | 演奏会・ライブ本番。オーディエンス数によって演者の感情入りが変化する。 |
| レコーディング（Recording） | スタジオ録音。オーディエンスなし・スナップショット記録重視。 |

### Milestone 6-1：ステージングモード設計
- プラクティス・ステージング・レコーディングの切り替えロジック
- ステージングモード時の感情パラメータ増幅係数設計
  - オーディエンス数に応じた係数変動
  - 「大舞台になるほど感情が入りやすくなる」表現

### Milestone 6-2：オーディエンスフィードバック設計
- オーディエンス数の受け取り・正規化
- フィールフィードバック（オーディエンスのリアクションがフィールトラックに影響する）の設計
- リアクションの種類と感情への影響マッピング
  ```
  コメント（通常）   → 希望・楽しみに小さく影響
  スーパーチャット    → 喜び・貪欲に強く影響（金額に比例）
  大量コメント流入   → 不安または楽しみに影響（演者次第）
  無反応（静寂）    → 虚無・不安に影響
  ```

### Milestone 6-3：ローカルステージング実装
- ダミーオーディエンス数での動作確認
- フィールフィードバックのリアルタイム反映確認

## Phase 8：ソーシャルプラットフォーム

**目標：** 演者・指揮者の共有・育成プラットフォームの構築

### 設計方針

ソーシャルプラットフォームはシン・PSGのコア仕様とは独立した層として構築する。
プラットフォームの形式は以下の2方式を検討する。

| 方式 | 説明 | メリット | デメリット |
|---|---|---|---|
| 中央集権型 | 単一サーバで演者・指揮者を管理 | 実装シンプル・ユーザー体験統一 | サーバ消失リスク |
| 連合型（Mastodon方式） | 各自がサーバインスタンスを持ち相互接続 | 分散・耐障害性高い | 実装複雑・めんどくさい |

### Milestone 8-1：プラットフォーム方式の確定
- 中央集権型と連合型のトレードオフ整理
- プロトタイプ規模での中央集権型から開始する方針の検討

### Milestone 8-2：演者・指揮者共有機能
- アップロード・ダウンロード・検索
- プロフィール・実績表示
- バージョン管理（スナップショット）

### Milestone 8-3：コミュニティ機能
- 演者・指揮者へのコメント・評価
- 演奏ログの公開・共有
- ランキング・人気演者の発見
