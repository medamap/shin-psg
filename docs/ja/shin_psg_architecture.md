# シン・PSG アーキテクチャドキュメント v0.1

## 概要

本ドキュメントはシン・PSG仕様書の補足文書であり、
演者・指揮者・癖パラメータの設計・定義・拡張方法を記述する
アーキテクチャリファレンスである。

感情エンジン テクニカルドキュメントが「内部でどう動くか」を定義するのに対し、
本ドキュメントは「どう設計・拡張するか」を定義する。

---

## 電子音楽ならではの抽象化

### 概念と実装の分離

生楽器では「概念」と「実装」を分離できない。

```
生楽器の場合
  バイオリンのビブラート → 弦を押さえた指を揺らす（物理的制約）
  フルートのビブラート  → 息のコントロール（別の物理的制約）
  楽器が変われば実装も変わり、かつ実装は楽器に縛られている
```

電子音源では概念と実装を完全に分離できる。
これがシン・PSGの設計の根幹であり、電子音楽ならではの強みである。

```
電子音源の場合
  「ビブラートをかける」という概念は共通
  PSG  → ピッチレジスタを高速で書き換えて実現
  FM   → LFOによるピッチ変調で実現
  PCM  → ピッチシフトで実現
  実装方法は異なるが概念は同一
```

演者は**抽象概念レベルの癖・感情パラメータを持つだけ**でよく、
どの音源で鳴らすかは実行時に解決される。
同じ演者をPSGで鳴らしてもFMで鳴らしても、
「ビブラートが好き」という性格は変わらないが、
その表現方法は音源の実装に委ねられる。

## クラス構造

### 演奏癖の抽象クラスと具象クラス

```
抽象クラス：演奏癖（PerformanceTrait）
  ├── ビブラート（Vibrato）
  │     パラメータ：好き度・開始タイミング・深さ揺れ・速度変化感度
  ├── トレモロ（Tremolo）
  │     パラメータ：好き度・感情連動強度・閾値
  └── ポルタメント（Portamento）
        パラメータ：好き度・カーブ形状・アンダーシュート・オーバーシュート

音源別具象クラス（抽象クラスを実装）

  PSG実装
    Vibrato    → ピッチレジスタの高速書き換え
    Tremolo    → ボリュームレジスタの高速書き換え
    Portamento → ピッチレジスタの段階的スキャン

  FM実装
    Vibrato    → LFO → ピッチ変調オペレータ
    Tremolo    → LFO → 音量変調オペレータ
    Portamento → キャリア周波数の補間処理

  PCM実装
    Vibrato    → ピッチシフト処理
    Tremolo    → ボリュームオートメーション
    Portamento → ピッチ補間処理
```

演者の定義ファイルは抽象クラスレベルで記述され、
音源への割り当ては演奏時に解決される。
これにより同一の演者ファイルを複数の音源で使い回すことができる。

### 演者の継承構造

演者は他の演者を基底として継承し、
差分のパラメータのみを上書きして定義できる。

```
基底演者（Base Performer）
  感情エンベロープ・感情アルゴリズム・演奏癖の
  すべてのパラメータを定義した演者

派生演者A（Derived Performer A）
  基底演者を継承
  上書き：ビブラート好き度のみ変更

派生演者B（Derived Performer B）
  基底演者を継承
  上書き：怒りのADSRのみ変更

派生演者C（Derived Performer C）
  派生演者Aをさらに継承
  上書き：ポルタメントのアンダーシュート量を変更
```

継承チェーンは複数段にわたって可能である。
未定義のパラメータは継承元の値が使われる。
これはFMのボイスコピーに近い感覚で、
「似たような性格の演者のバリエーション」を効率よく定義できる。

**継承の活用例：**

```
「古典的な奏者」（基底演者）
  → ビブラートは控えめ・ポルタメントなし・感情エンベロープは安定

「古典的な奏者（情熱的）」（派生）
  → 基底を継承し、怒りと喜びのSustainだけ高く設定

「古典的な奏者（晩年）」（派生）
  → 基底を継承し、悲しみと虚無のReleaseだけ長く設定
```

### 指揮者の継承構造

演者と同様に指揮者も継承して定義できる。

```
基底指揮者（Base Conductor）
  解釈傾向・カリスマ・伝達遅延の基本定義

派生指揮者A
  基底を継承し、カリスマのみ上書き

派生指揮者B
  基底を継承し、解釈傾向のみ上書き
```

## インターフェースとしての感情アルゴリズム

感情アルゴリズムのトポロジー（直列・並列・フィードバック）は
インターフェースとして定義され、演者はそれを実装する。

```
インターフェース：感情アルゴリズム（EmotionAlgorithm）
  定義：9感情の変調関係トポロジー
  実装：演者ごとに割り当てる

実装例A：直列アルゴリズム
  不安 → 怒り → ベクトル出力
  （焦りを含む怒りを表現する演者向け）

実装例B：並列アルゴリズム
  悲しみ ──┐
            ├→ ベクトル加算
  希望   ──┘
  （相反する感情を同時に抱えた演者向け）

実装例C：フィードバックアルゴリズム
  怒り → [自己変調] → ベクトル出力
    ↑_________________|
  （感情が暴走しやすい演者向け・発狂リスク高）
```

感情アルゴリズムは演者の定義とは独立して定義・保存・共有できる。
優れた感情アルゴリズムを別途配布し、
演者に組み込むという使い方も想定される。

## MMLとの優先順位

演者の癖パラメータとMMLの明示的な記述が競合する場合、
以下の優先順位で解決される。

```
優先度（高）
  MMLの明示的な記述
    ↓
  演者の癖パラメータ（感情ベクトルで変動）
    ↓
  音源のデフォルト動作
優先度（低）
```

MMLで明示的にビブラートを記述した場合は演者の癖より優先される。
MMLに記述がない場合は演者の癖パラメータが自動的に適用される。
これにより「演者に任せる」か「作曲家が指定する」かを
パート・ノート単位で選択できる。

## 演者定義ファイルの構造

演者定義ファイルは以下の構造を持つ。
具体的なファイルフォーマットは実装に委ねるが、
論理的な構造として以下を定義する。

```
演者定義ファイル
  ├── メタ情報
  │     名前・プロフィール・バージョン・作者・経験値
  │
  ├── 継承元（オプション）
  │     基底演者ファイルへの参照
  │
  ├── 感情エンベロープ（9感情 × ADSR）
  │     継承元からの差分のみ記述可能
  │
  ├── 感情アルゴリズム
  │     トポロジー定義またはアルゴリズムファイルへの参照
  │
  ├── 感情感度パラメータ
  │     楽観度・忍耐度・真面目度・感度・リミッター・減衰速度・追従性
  │
  ├── 演奏癖パラメータ
  │     ビブラート・トレモロ・ポルタメントの各パラメータ
  │
  └── 指揮者・リーダーパラメータ
        解釈傾向・カリスマ・伝達遅延・信頼感
```
