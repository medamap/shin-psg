# シン・PSG 感情エンジン テクニカルドキュメント v0.2

## 概要

本ドキュメントはシン・PSG仕様書の補足文書であり、
フィールトラックの感情データが演奏表現へ変換されるまでの
内部処理を定義するテクニカルリファレンスである。

感情エンジンの処理は以下の4段階で構成される。

```
[Stage 1] フィールトラック入力（9感情・独立カーブ）
    ↓
[Stage 2] 感情エンベロープ処理（各感情の時間変化整形）
    ↓
[Stage 3] 感情アルゴリズム処理（感情間の変調・合成）
    ↓
[Stage 4] Valence-Arousal ベクトル変換（θ, strength）
    ↓
[Stage 5] 解釈フィルタ（指揮者・リーダー・演者）
    ↓
[Stage 6] 演奏表現への反映
```

---

## Stage 1：フィールトラック入力

フィールトラックは作曲家が定義する感情の設計図であり、
9種類の感情パラメータが時間軸上の独立したカーブとして記述される。
各感情は0.0〜1.0の正規化された値を持ち、互いに独立して定義可能である。

| 感情 | 英語名 | Valence | Arousal |
|---|---|---|---|
| 希望 | Hope | + | 中 |
| 怒り | Anger | − | 高 |
| 悲しみ | Sadness | − | 低 |
| 喜び | Joy | + | 高 |
| 楽しみ | Fun | + | 中〜高 |
| 嫉妬 | Envy | − | 高 |
| 貪欲 | Greed | − | 高 |
| 虚無 | Void | − | 低 |
| 不安 | Anxiety | − | 中〜高 |

フィールトラックは作曲家の意図であり、この段階では演奏への影響は発生しない。
感情が複数同時に高い値を持つことは設計上許容されており、
その解釈・変換は後段の処理に委ねられる。

## Stage 2：感情エンベロープ処理

### 概要

フィールトラックから受け取った各感情の値は、
演者ごとに設定された感情エンベロープによって時間的に整形される。
これにより「立ち上がりが遅い」「いつまでも引きずる」などの
演者固有の感情特性が表現される。

感情エンベロープはADSR構造を持ち、FM音源のエンベロープと同様の概念である。
ただし制御対象は音量ではなく感情の強度値である。

### 感情エンベロープパラメータ（演者ごと・感情ごとに設定）

| パラメータ | 説明 |
|---|---|
| Attack | フィールトラックの値が上昇した際、演者内部の感情値が追従するまでの時間。短いほど即反応する短気な性格。長いほどじわじわ感情が高まるタイプ。 |
| Decay | 感情値がピークに達した後、Sustainレベルまで落ち着くまでの時間。短いほどすぐ冷める。長いほど余韻を引きずる。 |
| Sustain | 感情トリガーが持続している間の安定レベル（0.0〜1.0）。高いほど感情が持続して演奏に影響し続ける。低いほど一瞬だけ反応して収まる。 |
| Release | フィールトラックの感情値が下降した後、演者内部の感情値がゼロに戻るまでの時間。短いほどすぐ忘れる。長いほどいつまでも引きずる性格。 |

### 設計上の注意

9感情×4パラメータ（ADSR）で演者一人あたり36個のエンベロープパラメータが存在する。
これらの組み合わせによって演者の感情的な「癖」が決まるため、
意図した感情表現をする演者を設計するには、
感情と演奏パラメータの関係を深く理解した上での調整が必要である。
FM音源のオペレータ設定と同様に、玄人向けのパラメータ群である。

同じ演者であっても、楽曲のフィールトラックの書き方次第で全く異なる挙動を示す。
「この演者はこういう楽曲に合う」という相性の概念が自然に生まれる。

## Stage 3：感情アルゴリズム処理

### 概要

FM音源においてオペレータの接続トポロジー（アルゴリズム）が音色を決定するように、
シン・PSGでは感情間の変調関係（感情アルゴリズム）が
最終的なValence-Arousalベクトルへの変換方法を決定する。

### キャリア感情とモジュレータ感情

| 役割 | 定義 |
|---|---|
| キャリア感情（Carrier） | Valence-Arousalベクトルへ直接寄与する感情 |
| モジュレータ感情（Modulator） | キャリア感情の変換特性を変調する感情 |

**重要：キャリアとモジュレータの関係は動的に決定される。**

FMのキャリア・モジュレータはアルゴリズムで固定されるが、
シン・PSGでは各時刻においてフィールトラックの感情強度によって
キャリアとモジュレータの関係が動的に変化する。
強度が高い感情がキャリアになり、
その次に強い感情がモジュレータとして作用するのが基本的な振る舞いである。
これはFMにはない概念であり、シン・PSG独自の拡張である。

### 感情アルゴリズムのトポロジー

演者ごとに感情アルゴリズムのトポロジーを定義する。
基本的なトポロジーは以下の3種類である。

**直列接続（Series）**
```
モジュレータ感情 → キャリア感情 → Valence-Arousalベクトル
```
モジュレータがキャリアの変換特性を変調してから最終出力へ至る。
効果が増幅されやすく、複雑な感情の質感が生まれる。
例：不安が怒りを変調すると「焦りを含む怒り」「怯えた怒り」になり、
　　θは怒り方向を向くがstrengthが不安定に揺れる。

**並列接続（Parallel）**
```
感情A ──┐
         ├→ ベクトル加算 → Valence-Arousalベクトル
感情B ──┘
```
複数の感情が独立してベクトルに寄与し、最終的にベクトル加算される。
シンプルな合成だが、相反する感情が同時に並列接続されると
ベクトルが引き合ってstrengthが低下する。
感情的に揺れているが表現に出にくい状態。

**フィードバック接続（Feedback）**
```
感情A → [自己変調] → Valence-Arousalベクトル
  ↑______________|
```
ある感情が自分自身を変調するループ構造。
FM音源のフィードバックが倍音を増加させたように、
感情が自己強化されやすく暴走リスクが高まる。
発狂状態（Breakdown）への最短経路になり得る。
高い表現力を持つが取り扱いには注意が必要である。

### 変調の効果例

| キャリア | モジュレータ | 結果の感情的質感 |
|---|---|---|
| 怒り | 不安 | 焦りを含む怒り。strengthが不安定に揺れる。 |
| 悲しみ | 嫉妬 | 悲しみの中に攻撃性が滲む。低Arousalの中で突発的にArousalが上昇する瞬間が生まれる。 |
| 喜び | 虚無 | 空虚な喜び。テンションが上がりきらない。快側のベクトルだがstrengthが抑制される。 |
| 希望 | 不安 | 不安定な期待感。θは快側を向くがstrengthが揺れ続ける。 |
| 貪欲 | 嫉妬 | 攻撃的な欲望。高Arousal・不快側でstrengthが増大しやすい。 |

## Stage 4：Valence-Arousal ベクトル変換

### 概要

Stage 3までの処理を経た感情データを、
Valence-Arousal平面上の2次元ベクトル（θ, strength）に変換する。

```
Valence軸（横軸）: 快（+）← → 不快（−）
Arousal軸（縦軸）: 高覚醒（+）↑ ↓ 低覚醒（−）
```

### 9感情の基本配置

```
              高Arousal
                  ↑
    怒り  不安  貪欲  嫉妬
不快 ←─────────────────→ 快
         悲しみ  虚無       希望 喜び 楽しみ
                  ↓
              低Arousal
```

### θとstrengthの定義

| パラメータ | 定義 |
|---|---|
| θ（シータ） | Valence-Arousal平面上のベクトルの角度。感情の「方向性・質」を表す。 |
| strength（強度） | ベクトルの大きさ。感情が演奏に影響する強さを表す。0に近いほど演奏への影響が小さい。 |

相反する感情（例：喜びと虚無）が同時にフィールトラックに存在すると、
ベクトルが互いに打ち消し合いstrengthが低下する。
これは「感情的に揺れているが表現に出にくい」状態を自然に表現する。

## Stage 5：解釈フィルタ

### 概要

Stage 4で生成されたValence-Arousalベクトルは、
指揮者・リーダー・演者の解釈フィルタを通じてさらに変質する。
誰が解釈するかによって同じフィールトラックでも全く異なるベクトルが生成される。

詳細はシン・PSG仕様書「演奏モード」の項を参照。

### 解釈フィルタの混合比率（リーダーモード時）

```
最終ベクトル = リーダーのベクトル × 信頼感
            + 演者独自のベクトル × （1.0 − 信頼感）
```

信頼感が1.0の演者はリーダーの解釈に完全に従い、
0.0の演者は完全に独自解釈で演奏する。

## Stage 6：演奏表現への反映

### 概要

最終的なValence-Arousalベクトル（θ, strength）が
ノートオンのタイミング・アタック・リリースの変化として演奏に反映される。

### θによる演奏特性の変化

**高Arousal・不快側（怒り・不安・貪欲・嫉妬方向）**
- ノートオンが前のめりになる（タイミングが早まる）
- アタックが強く・速くなる
- リリースが短くなる（ぶつ切り気味）
- テンポが速方向に揺れる
- 音量が大きくなる

**低Arousal・不快側（悲しみ・虚無方向）**
- ノートオンが後ろに引っ張られる
- アタックが弱く・遅くなる
- リリースが長くなる（余韻を引きずる）
- テンポが遅方向に揺れる
- 音量が小さくなる

**快側（希望・喜び・楽しみ方向）**
- ノートオンのタイミングが安定する
- アタックが自然な強さになる
- リリースが程よく伸びる
- テンポが安定する
- 音量が中〜大になる

**嫉妬の特殊効果**
- 他パートとの音量バランスが崩れる方向に働く
- 自分のパートを前に出そうとする挙動が生まれる
- アンサンブルとして演奏している場合に他演者との干渉が発生しやすい

### strengthによる効果量の制御

strengthが高いほど各演奏効果が強くなる。
strengthが0に近いほど演奏への影響が消失し、通常の演奏に近づく。

## Stage 6-B：演奏癖パラメータ

### 概要

シン・PSGの演者は、ノートオン・アタック・リリースといった基本的な演奏表現に加えて、
ビブラート・トレモロ・ポルタメントといった奏法上の「癖」を持つ。
これらは演者固有のパラメータとして定義され、感情ベクトル（θ, strength）と連動して変化する。

**重要な設計方針：MMLへの記述は不要。**

ビブラート・トレモロ・ポルタメントはMMLで明示的に記述しなくても、
演者の癖パラメータに従って自動的に演奏に付加される。
MMLで明示的に記述した場合は演者の癖より優先される（上書き）。
つまり「演者に任せる」か「作曲家が指定する」かを選べる設計である。

---

### ビブラート癖パラメータ

| パラメータ | 説明 |
|---|---|
| ビブラート好き度（Vibrato Affinity） | どれだけビブラートをかけたがるか。0でほぼかけない、1.0で積極的にかける。 |
| 開始タイミング（Vibrato Delay） | ノートオン後、ビブラートが始まるまでの時間。短いほど最初から揺れる、長いほど音が安定してから揺れ始める。 |
| 深さ揺れ（Vibrato Depth Fluctuation） | ビブラートの深さが一定か、感情に連動して揺れるか。高いほど感情が高まるとビブラートが深くなる。 |
| 速度変化感度（Vibrato Rate Sensitivity） | 感情の変化に対してビブラートの速度がどれだけ変化するか。怒り方向でビブラートが速くなるか、悲しみ方向で遅くなるか、など。 |

**感情との連動例：**
```
怒り方向（高Arousal・不快）  → ビブラートが速く・深くなる
悲しみ方向（低Arousal・不快）→ ビブラートが遅く・深くなる
虚無方向                     → ビブラートが薄くなる・消える
不安方向                     → ビブラートの深さが不規則に揺れる
```

---

### トレモロ癖パラメータ

| パラメータ | 説明 |
|---|---|
| トレモロ好き度（Tremolo Affinity） | どれだけトレモロをかけたがるか。 |
| 感情連動強度（Tremolo Emotion Sensitivity） | 感情の変化に対してトレモロがどれだけ増減するか。不安・怒りが高まると意図せずトレモロが混入する、など。 |
| 閾値（Tremolo Threshold） | このstrength値を超えた時にトレモロが発生し始める。低いほど少しの感情変化でもトレモロが出る。 |

**感情との連動例：**
```
不安方向   → トレモロが意図せず混入しやすい
怒り方向   → トレモロが強く・速くなる
虚無方向   → トレモロが消える・無気力な平坦さになる
```

---

### ポルタメント癖パラメータ

ポルタメントはMMLで指定されていない場合でも演者の癖として付加される。
MMLでポルタメントが指定されている場合は、そのポルタメントに対して癖が上乗せされる。

#### 基本カーブ

| パラメータ | 説明 |
|---|---|
| ポルタメント好き度（Portamento Affinity） | どれだけポルタメントをかけたがるか。 |
| カーブ形状（Portamento Curve） | 音程移動の基本カーブ形状。イーズイン（ゆっくり始まって速く到達）、イーズアウト（速く始まってゆっくり到達）、S字、直線など。 |

#### アンダーシュート（下から探るように上がる）

音程が上昇する前に一瞬目標音程より下に外れてから上昇する挙動。
弦楽器・声楽奏者が無意識に行う自然な癖。

| パラメータ | 説明 |
|---|---|
| アンダーシュート量（Undershoot Amount） | 上昇前に下がる量。0でなし。感情に連動して変化する。 |
| アンダーシュートカーブ（Undershoot Curve） | 下がってから上昇へ転じるカーブの形状。 |

```
通常ポルタメント  :  ────/────
アンダーシュートあり:  ──╲/────
                        （一瞬下がってから上昇）
```

#### オーバーシュート（行きすぎて戻る）

目標音程に到達した後、一瞬行きすぎてから正しい音程に戻る挙動。

| パラメータ | 説明 |
|---|---|
| オーバーシュート量（Overshoot Amount） | 到達後に行きすぎる量。0でなし。感情に連動して変化する。 |
| オーバーシュートカーブ（Overshoot Curve） | 行きすぎてから戻るカーブの形状。 |

```
通常ポルタメント    :  ────/──
オーバーシュートあり:  ────/╲─
                          （少し行きすぎて戻る）
```

#### 感情との連動例

```
怒り方向
  → オーバーシュートが大きくなる（前のめりで行きすぎる）
  → アンダーシュートはしない（下から探る余裕がない）
  → カーブがイーズイン（速く到達する）

悲しみ方向
  → アンダーシュートが大きくなる（下から探るように上がる）
  → カーブがイーズアウト（ゆっくりと到達する）
  → オーバーシュートは小さい

不安方向
  → アンダーシュート・オーバーシュートが両方出る（不安定な音程）
  → カーブが不規則に揺れる

希望・喜び方向
  → アンダーシュートが自然な量（音楽的な表現として機能する）
  → カーブがS字（滑らか）
```

## 育成と経験値

### 概要

演奏後、演者・リーダー・指揮者はその演奏の経験値を得る。
経験値は別ファイルに記録され、次回演奏時にキャッシュとして読み込まれる。

### 育成の場所

育成環境は問わない。以下のいずれも有効である。

- **ローカル定義** : パラメータを直接設定・調整して育成する
- **ソーシャルプラットフォーム** : プラットフォーム上で育成し、エクスポートして演奏に使用する

### ファイルとアイデンティティ

演者・リーダー・指揮者は名前とプロフィールを持ち、
経験値の蓄積によって世界で唯一のユニークな個体として育てることができる。
育成したファイルはエクスポートして共有・配布が可能である。

### 設計方針

パラメータ体系はFM音源と同様の玄人向け設計とする。
感情エンベロープ・感情アルゴリズム・解釈傾向の組み合わせを深く理解した上で
初めて意図した表現をする演者を設計できる。
「思い通りの感情表現をする演者を作ることは難しい」という前提のもと、
試行錯誤と育成の楽しさを本仕様の文化的価値の一部とする。
