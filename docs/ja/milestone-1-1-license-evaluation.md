## 調査概要

シン・PSGの実装で使用を検討している音源エミュレータライブラリ・オーディオ出力ライブラリ計7点について、
以下の観点でライセンスを精査した。

- 商用利用可否
- 改変・再配布条件
- スタティックリンク時の条件
- GPL汚染リスク
- 帰属表示（著作権表示）の要件

### Nuked-OPM

| 項目 | 内容 |
|---|---|
| ライセンス | LGPL-2.1 |
| 著作権者 | nukeykt |
| 商用利用 | ✅ 可能（LGPL条件を遵守した上で） |
| 改変 | △ 改変版はLGPL-2.1で公開が必要 |
| 再配布 | △ ライセンス表記と変更内容の開示が必要 |
| スタティックリンク | △ 後述のLGPL静的リンク条件を参照 |
| GPL汚染 | 低（LGPL自体はアプリ本体を汚染しない） |

**対応チップ：** OPM (YM2151)

**LGPL静的リンク時の注意点：**
LGPLライブラリをスタティックリンクする場合、アプリ本体のソースコード開示は不要だが、
ユーザーがライブラリ部分を差し替えて再リンクできるようにする必要がある（オブジェクトファイルの提供または再リンク手順の文書化）。
動的リンク（DLL / .so）であれば帰属表示のみで済む。

**評価：** ymfmがOPM(YM2151)に対応しているため、Nuked-OPMは**不要**。
ymfmで代替することでLGPLの制約から完全に解放される。採用は見送る。

## ライセンスに関する重要事項

### LGPL動的リンク vs 静的リンクの違い

| リンク方式 | 条件 |
|---|---|
| 動的リンク（DLL / .so / .dylib） | ライブラリのライセンス表記のみ必要。アプリ本体のソース開示不要。 |
| 静的リンク（.a / .lib） | ユーザーがライブラリを差し替えて再リンクできるよう配慮が必要（オブジェクトファイル提供または再リンク手順の文書化）。アプリ本体のソース開示は不要。 |

### GPL汚染とは

GPLライセンスのコードをリンク（静的・動的いずれも）して配布すると、
そのアプリケーション全体がGPLの条件（ソースコードの開示・配布）に従う義務が生じる。
これを「GPL汚染（GPL contamination）」と呼ぶ。

商用・クローズドソース開発を行う場合、GPLコードの組み込みは
ビジネスモデルと根本的に矛盾する可能性があるため、原則として回避する。

## 帰属表示の実装方針

採用ライブラリの著作権表示はアプリケーションの以下の場所に記載する。

- `NOTICE` ファイル（ルートに配置・配布必須）
- ソースコード内の対応するファイルまたはモジュールのヘッダコメント
- GUI版を実装する場合は「ライセンス情報」画面への記載

記載が必要な著作権表示（現時点での確定分）：

```
ymfm - Copyright (c) 2021 Aaron Giles
BSD-3-Clause License

ayumi - Copyright (c) true-grue
MIT License

miniaudio - Copyright (c) 2025 David Reid
Unlicense / MIT No Attribution License
```
