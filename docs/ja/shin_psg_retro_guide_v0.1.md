## 設計方針

### Z80共通コアの概念

X1・MSX・PC-88はすべてZ80アーキテクチャを使用しているため、
サウンドドライバのアルゴリズム本体は共通ソースコードとして実装できる。

分離の原則はモダンプラットフォームの `src/core/` と `src/platform/` の関係と同一である。

```
retro/z80/core/    ← Z80共通コード（アルゴリズム本体）
  driver/          ← サウンドドライバアルゴリズム
  feel/            ← 感情エンジン簡略実装
  mml/             ← MMLバイナリデコード処理

retro/z80/x1/platform/   ← X1固有（割り込み・レジスタ）
retro/z80/msx/platform/  ← MSX固有（割り込み・レジスタ）
retro/z80/pc88/platform/ ← PC-88固有
```

共通コードは各機種のエントリポイントからAILZ80ASMの `INCLUDE` ディレクティブで参照する。
コアコードはハードウェアレジスタへの直接アクセスを一切含まず、
すべてのハードウェア依存処理は `platform/` 以下に分離する。

## 割り込みとテンポ管理

### 問題の本質

Z80音楽ドライバは割り込みドリブンで動作する。
割り込みが発生するたびに「チック（tick）」を1カウントし、
チャンネルごとのウェイトカウンタをデクリメントしてノートイベントを処理する。

テンポはこのチックレートに依存するため、機種によってチックレートが異なると
同一のMMLバイナリから異なるテンポで再生される問題が生じる。

### 機種別の割り込みソースと特性

**Sharp X1 — CTC割り込み**

```
X1のCTC（Z80 CTC: Counter/Timer Circuit）を使用して
任意の周期で割り込みを発生させることができる。

例：CTCを300Hzに設定した場合
  テンポ120BPM = 2拍/秒 = 1拍 = 150チック
  最小時間単位 = 1/300秒 ≈ 3.3ms
  十分に細かい時間分解能が得られる
```

**MSX — VDP V-SYNC割り込み**

```
MSXのVDP（Video Display Processor）がV-SYNC時に発生する割り込みに相乗りする。
周波数はNTSC環境で固定60Hz（PAL環境では50Hz）。

例：60Hzの場合
  テンポ120BPM = 2拍/秒 = 1拍 = 30チック
  最小時間単位 = 1/60秒 ≈ 16.7ms
  テンポ表現の分解能はX1より低いが、音楽ドライバとしては十分実用的
```

### 解決策：チック抽象化

共通コードはチックレートを知らなくてよい設計とする。
機種固有の初期化コードがチックレートを定数として提供し、
MMLバイナリのコンパイル時にコンパイラが各機種のチックレートに合わせて
ウェイト値を変換する。

```
; 共通コードのイメージ（擬似コード）
; チックレートに依存しない処理
TICK_HANDLER:
    ; 全チャンネルのウェイトカウンタをデクリメント
    ; ウェイト = 0 になったチャンネルのノートイベントを処理
    ; チックレートは知らなくてよい

; 機種側が提供する定数（X1の例）
TICKS_PER_SEC   EQU 300     ; CTCで設定したレート

; MSXの例
TICKS_PER_SEC   EQU 60      ; VDP V-SYNC固定
```

MMLコンパイラはターゲット指定（`--target x1` / `--target msx`等）に応じて
チックレートに合わせたウェイト値を埋め込んだバイナリを生成する。

## ビルドツール：AILZ80ASM

### 概要

- リポジトリ：https://github.com/AILight/AILZ80ASM
- 言語：C#（.NET 8）
- 実行形式：自己完結バイナリ（Windows/macOS/Linux対応、.NET不要）
- ライセンス：MIT
- 設定ファイル：`AILZ80ASM.json`（入出力・オプション設定）

### インストール

GitHubのReleasesページから対応プラットフォームのバイナリをダウンロードし、
パスの通った場所に配置する。

### 基本的な使い方

```bash
# 基本コンパイル
AILZ80ASM input.asm

# オプション指定
AILZ80ASM --output-format MZT --output main.mzt main.asm

# 設定ファイル使用（プロジェクトルートにAILZ80ASM.jsonを置く）
AILZ80ASM main.asm
```

### AILZ80ASM.json の配置

設定ファイルは各機種ディレクトリに配置する。
出力形式が機種ごとに異なるため、共有はしない。

```
retro/z80/x1/AILZ80ASM.json   ← MZT/CMT出力設定
retro/z80/msx/AILZ80ASM.json  ← ROM/CAS出力設定
retro/z80/pc88/AILZ80ASM.json ← 調査待ち
```

### CMakeからの呼び出し（任意）

モダンビルドと一緒にレトロターゲットをビルドしたい場合、
ルートCMakeLists.txtから以下のように呼び出すことができる（必須ではない）。

```cmake
add_custom_target(retro-x1
    COMMAND make -C ${CMAKE_SOURCE_DIR}/retro/z80/x1
    COMMENT "Building Sharp X1 target with AILZ80ASM"
)

add_custom_target(retro-msx
    COMMAND make -C ${CMAKE_SOURCE_DIR}/retro/z80/msx
    COMMENT "Building MSX target with AILZ80ASM"
)
```

通常のレトロ開発は各機種ディレクトリで `make` を実行する。

## 感情エンジンのZ80移植方針

### 基本方針

シン・PSGの感情エンジン（Stage 1〜6）はモダンプラットフォームでのフルセット実装を
Phase 2〜3で完成させた後、Z80移植版を設計する。

「まずフルセットで実装し、Z80上で実際に計測してから削る」が原則であり、
削りすぎて感情エンジンの面白さが失われないように注意する。

### Z80での制約

| 制約 | 内容 |
|---|---|
| FPUなし | θ・strengthの浮動小数点演算は固定小数点（8bit/16bit）で代替が必要 |
| メモリ制約 | Z80のアドレス空間は64KB（バンク切り替えで拡張可能な場合もある） |
| 演算速度 | 積和演算はソフトウェアで実装するため低速。ルックアップテーブル活用が有効 |

### 簡略化の候補（計測後に判断）

以下は将来の最適化候補であり、現時点では確定しない。

- 感情パラメータのbit数削減（float → 8bit固定小数点）
- `atan2` のルックアップテーブル化
- 感情エンベロープのADSRをより単純なカーブで近似
- チック単位での更新頻度を下げる（毎チックではなく数チックに1回）
- 9感情をより少数に集約する（サブセット感情定義）

### Z80感情エンジンの実装順序

1. フルセット版（モダンプラットフォーム）の完成を待つ
2. Z80で動く最小の感情処理（固定小数点ADSR + 簡易ベクトル変換）を実装
3. 実機またはエミュレータで負荷計測
4. 許容範囲に収まるまで段階的に簡略化

## 機種別注意事項

### Sharp X1

- CTC設定によりタイマー解像度を自由に選択できる
- メモリマップ・I/Oポートアドレスの確認が必要
- PSGはAY-3-8910互換（ポートアドレス要確認）

### MSX

- VDP V-SYNC割り込み（INT）を使用する
- PAL環境では50Hzになることに注意（NTSC/PAL判定処理の検討）
- PSGはAY-3-8910（I/Oポート経由でアクセス）
- MSX-BASIC / MSX-DOS上で動作させるか、ROMカートリッジとして実装するかで構造が変わる

### PC-88

- 詳細は調査中。判明次第本ドキュメントに追記する
