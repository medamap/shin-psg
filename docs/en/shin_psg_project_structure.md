# Shin-PSG Project Structure Guide v0.1

This document defines the directory structure, build system, and development policies of the Shin-PSG repository.
It serves as a reference for onboarding new contributors and for making decisions about document and code placement.

## Directory Structure

```
shin-psg/
│
├── README.md                    # Japanese README root
├── README.en.md                 # English README (future)
├── CMakeLists.txt               # CMake root (manages all modern targets)
│
├── docs/                        # Documentation
│   ├── ja/                      # Japanese documents (primary language)
│   ├── en/                      # English documents (translated; generated by skill)
│   └── progress/                # Milestone completion records and decision summaries
│
├── src/                         # Source code for modern platforms (C++17)
│   ├── core/                    # Platform-independent core
│   │   └── CMakeLists.txt
│   ├── platform/                # Implementations for modern OS and environments
│   │   ├── windows/             # Windows-specific (audio output, file I/O, etc.)
│   │   ├── macos/
│   │   ├── linux/
│   │   ├── android/             # C++ code for Android NDK side (JNI bindings, etc.)
│   │   ├── ios/
│   │   ├── wasm/                # Emscripten bindings and JS glue code
│   │   └── rpi-baremetal/       # RPi bare-metal (gcc-arm-none-eabi; under CMake)
│   └── retro/                   # Reserved for future use (currently unused)
│
├── retro/                       # Retro and assembler-based (outside CMake scope)
│   └── z80/                     # Z80 architecture common
│       ├── core/                # Z80 shared code (referenced via INCLUDE from each machine)
│       │   ├── driver/          # Sound driver algorithm body
│       │   ├── feel/            # Simplified Feel Engine (Phase 2+)
│       │   └── mml/             # MML binary decode processing
│       ├── x1/                  # Sharp X1-specific
│       │   ├── platform/        # CTC interrupt handler and X1-specific register definitions
│       │   ├── AILZ80ASM.json   # Output format: MZT/CMT
│       │   └── Makefile
│       ├── msx/                 # MSX-specific
│       │   ├── platform/        # VDP interrupt handler and MSX-specific code
│       │   ├── AILZ80ASM.json   # Output format: ROM/CAS
│       │   └── Makefile
│       └── pc88/                # PC-88-specific (details pending investigation)
│           ├── platform/
│           ├── AILZ80ASM.json
│           └── Makefile
│
├── platform/                    # IDE project files and toolchain definitions
│   ├── windows/                 # Visual Studio solution, .vcxproj, etc.
│   ├── android/                 # Android Studio project files
│   │                            #   → references src/core/ and src/platform/android/ via relative paths
│   ├── ios/                     # Xcode project
│   └── cmake/
│       └── toolchains/          # CMake cross-compilation toolchain files
│           ├── android.cmake
│           ├── wasm.cmake
│           └── rpi-baremetal.cmake
│
├── res/                         # Resource files
│   ├── mml/                     # Sample MML files
│   ├── performers/              # Sample Performer definition files (PML)
│   └── conductors/              # Sample Conductor definition files
│
└── research/                    # Verification code (organized per milestone; temporary items deleted)
    └── milestone-X-Y-name/      # Example: milestone-1-2-sound-verification
```

## Platform Classification

### Modern Platforms (`src/` scope)

Targets that implement the full Shin-PSG specification using C++17.

| Platform | Location | Build System | Notes |
|---|---|---|---|
| Windows | `src/platform/windows/` | CMake | VS2022 recommended |
| macOS | `src/platform/macos/` | CMake | Xcode or CLT |
| Linux | `src/platform/linux/` | CMake | |
| Android | `src/platform/android/` | CMake + NDK | IDE separated into `platform/android/` |
| iOS | `src/platform/ios/` | CMake + Xcode | IDE separated into `platform/ios/` |
| WASM | `src/platform/wasm/` | CMake + Emscripten | |
| RPi Bare-Metal | `src/platform/rpi-baremetal/` | CMake + gcc-arm-none-eabi | No OS; C/C++ |

### Retro Platforms (`retro/` scope)

Targets that implement a subset using Z80 assembler. Build system is outside CMake scope.

| Platform | Location | Assembler | Output Format |
|---|---|---|---|
| Sharp X1 | `retro/z80/x1/` | AILZ80ASM | MZT / CMT |
| MSX | `retro/z80/msx/` | AILZ80ASM | ROM / CAS |
| PC-88 | `retro/z80/pc88/` | AILZ80ASM | Pending investigation |

## Build System Policy

### CMake (Modern Targets)

- The root `CMakeLists.txt` manages all modern targets
- Each directory has its own `CMakeLists.txt`, added as a subdirectory from the parent
- Cross-compilation toolchain files are centralized in `platform/cmake/toolchains/`
- AILZ80ASM builds can optionally be invoked via `add_custom_target` (see `shin_psg_retro_guide.md` for details)

### AILZ80ASM (Retro Targets)

- Invoked from each machine directory's `Makefile`
- `retro/z80/core/` is referenced from each machine via INCLUDE directives (assembled per machine)
- See also: [shin_psg_retro_guide.md](shin_psg_retro_guide.md)

## Branch Strategy

```
main        ← Stable; tagged releases
└── develop ← Integration branch
    ├── milestone/1-1-license-review
    ├── milestone/1-2-sound-verification
    ├── milestone/1-3-tech-selection
    └── milestone/1-4-project-structure
```

- Each milestone is worked on in a branch named `milestone/X-Y-name` (lowercase English, hyphen-separated)
- After milestone completion, merge into `develop` and add a decision summary to `docs/progress/`
- Merging to `main` is done at stable points such as Phase milestones

## Code and Document Placement Rules

### Documentation

- Japanese is the primary language. Update Japanese versions first; English versions are generated by skill
- Specification and design documents go in `docs/ja/`
- Decision summaries at milestone completion go in `docs/progress/`
- Verification code in `research/` should be deleted after results are documented (unless worth preserving as reference)

### Source Code

- `src/core/` must not contain platform-specific headers, libraries, or APIs
- `retro/z80/core/` must not contain direct hardware register access (machine-specific code belongs in each machine's `platform/`)
- Resource file paths are written as relative paths from `res/`

---

## Verification Code Management

`research/` subdirectories are organized by milestone number.

| Type | Handling |
|---|---|
| Temporary operational verification code | Record results in `docs/progress/`, then delete |
| Code worth preserving as reference material | Keep in `research/` as-is |
| Code that became the basis for production implementation | Move to `src/` or `retro/`, then delete the `research/` version |
